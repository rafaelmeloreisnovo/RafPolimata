# BCM2835 Peripheral Architecture Reference (Raspberry Pi)

This document covers the BCM2835/BCM2837 peripheral map as used in the RafPolimata
project. All register addresses, offsets, and bit definitions are taken from the
project source files RAF_021 through RAF_035. Address constants are confirmed
against those files.

---

## 1. Physical Peripheral Base Addresses

The BCM2835 (Pi 1/Zero) uses a peripheral base at 0x20000000. The BCM2837 (Pi 3)
maps the same peripheral block at 0x3F000000. All RafPolimata files use the
BCM2837 base, which is forward-compatible.

| Peripheral | Physical Base Address | Source constant |
|------------|----------------------|-----------------|
| GPIO       | 0x3F200000           | `BCM_GPIO_BASE` (RAF_021) |
| SPI0       | 0x3F204000           | (offset +0x4000 from GPIO base) |
| PWM        | 0x3F20C000           | (offset +0xC000 from GPIO base) |
| Clock Manager (CM) | 0x3F101000 | `CM_PWMCTL_OFFSET` context (RAF_031) |
| DMA        | 0x3F007000           | (BCM2835 datasheet; used by RAF_032/033) |
| BSC1 (I2C) | 0x3F804000           | (BSC1 secondary I2C bus) |

All peripherals are accessed via `mmap` of `/dev/mem` or `/dev/gpiomem`. In
the project, the caller maps the relevant base and passes a `volatile uint32_t *`
pointer. Register offsets are specified in bytes and converted to word indices
by dividing by 4 before use as array subscripts.

## 2. GPIO Peripheral (base 0x3F200000)

Source files: RAF_021, RAF_022, RAF_023, RAF_035.

### 2.1 Register Map

| Register  | Byte offset | Word index | Description |
|-----------|-------------|------------|-------------|
| GPFSEL0   | 0x00        | 0          | Function select GPIO 0-9 |
| GPFSEL1   | 0x04        | 1          | Function select GPIO 10-19 |
| GPFSEL2   | 0x08        | 2          | Function select GPIO 20-29 |
| GPFSEL3   | 0x0C        | 3          | Function select GPIO 30-39 |
| GPFSEL4   | 0x10        | 4          | Function select GPIO 40-49 |
| GPFSEL5   | 0x14        | 5          | Function select GPIO 50-53 |
| (reserved) | 0x18       | —          | — |
| GPSET0    | 0x1C        | 7          | Pin output set GPIO 0-31 |
| GPSET1    | 0x20        | 8          | Pin output set GPIO 32-53 |
| (reserved) | 0x24       | —          | — |
| GPCLR0    | 0x28        | 10         | Pin output clear GPIO 0-31 |
| GPCLR1    | 0x2C        | 11         | Pin output clear GPIO 32-53 |
| (reserved) | 0x30       | —          | — |
| GPLEV0    | 0x34        | 13         | Pin level GPIO 0-31 |
| GPLEV1    | 0x38        | 14         | Pin level GPIO 32-53 |
| (reserved) | 0x3C       | —          | — |
| GPEDS0    | 0x40        | 16         | Event detect status 0 |
| GPEDS1    | 0x44        | 17         | Event detect status 1 |
| GPREN0    | 0x4C        | 19         | Rising edge detect enable 0 |
| GPREN1    | 0x50        | 20         | Rising edge detect enable 1 |
| GPFEN0    | 0x58        | 22         | Falling edge detect enable 0 |
| GPFEN1    | 0x5C        | 23         | Falling edge detect enable 1 |

Word indices above are used as array subscripts in the project source, e.g.,
`gpio_base[0x34 / 4]` for GPLEV0 (RAF_021, line 46).

The named macros in RAF_035 are:

```c
#define GPFSEL0_WORD  (0x00u / 4u)   // 0
#define GPSET0_WORD   (0x1Cu / 4u)   // 7
#define GPCLR0_WORD   (0x28u / 4u)   // 10
#define GPLEV0_WORD   (0x34u / 4u)   // 13
#define GPEDS0_WORD   (0x40u / 4u)   // 16
#define GPREN0_WORD   (0x4Cu / 4u)   // 19
#define GPFEN0_WORD   (0x58u / 4u)   // 22
```

### 2.2 GPFSEL Function Codes

Each GPFSEL register holds 10 three-bit fields (bits 2:0 for GPIO 0, bits 5:3
for GPIO 1, etc.):

| Code | Function |
|------|----------|
| 000  | Input    |
| 001  | Output   |
| 100  | ALT0     |
| 101  | ALT1     |
| 110  | ALT2     |
| 111  | ALT3     |
| 011  | ALT4     |
| 010  | ALT5     |

### 2.3 Event Detection (GPEDS0)

GPEDS0 is a Write-1-to-Clear (W1C) register. A bit is set when a detected event
occurs on the corresponding GPIO pin. To clear the flag, write 1 to that bit
position. Writing 0 has no effect.

The project's poll function (RAF_035) implements this as:
```c
if (gpio_base[GPEDS0_WORD] & pin_mask) {
    gpio_base[GPEDS0_WORD] = pin_mask;  // clear W1C
    return 1;
}
```

Note from RAF_035: the W1C behaviour cannot be simulated with a plain volatile
array in self-test mode; only hardware implements the hardware-side clear.

## 3. SPI0 Peripheral (base 0x3F204000)

Source file: RAF_029.

### 3.1 Register Offsets

| Register | Byte offset | Word index (`/4`) | Description |
|----------|-------------|-------------------|-------------|
| CS       | 0x00        | 0 (`SPI0_CS_OFFSET`)   | Control and Status |
| FIFO     | 0x04        | 1 (`SPI0_FIFO_OFFSET`) | TX/RX FIFO data |
| CLK      | 0x08        | 2 (`SPI0_CLK_OFFSET`)  | Clock Divider |

### 3.2 CS Register Bit Definitions

| Bit | Macro           | Direction | Description |
|-----|-----------------|-----------|-------------|
| 4   | SPI0_CS_CLEAR_TX | W        | Clear TX FIFO |
| 5   | SPI0_CS_CLEAR_RX | W        | Clear RX FIFO |
| 7   | SPI0_CS_TA      | R/W       | Transfer Active (1=start) |
| 16  | SPI0_CS_DONE    | R         | Transfer done |
| 17  | SPI0_CS_RXD     | R         | RX FIFO has data |
| 18  | SPI0_CS_TXD     | R         | TX FIFO has space for data |

### 3.3 Transfer Sequence

The canonical single-byte full-duplex transfer sequence from RAF_029:
1. Write `CLEAR_RX | CLEAR_TX` to CS to flush both FIFOs.
2. Write `TA` to CS to assert Transfer Active (chip select).
3. Poll CS until `TXD = 1` (TX FIFO accepts data).
4. Write transmit byte to FIFO.
5. Poll CS until `DONE = 1`.
6. Read received byte from FIFO.
7. Clear `TA` in CS to deassert Transfer Active.

Clock rate example from RAF_029:
```c
mmio_base[SPI0_CLK_OFFSET] = 256u;
// 250 MHz / 256 ≈ 976 kHz SPI clock
```

## 4. BSC1 / I2C Peripheral (base 0x3F804000)

Source file: RAF_030.

### 4.1 Register Offsets

| Register | Word index | Macro           | Description |
|----------|------------|-----------------|-------------|
| C        | 0          | `BSC_C_OFFSET`    | Control |
| S        | 1          | `BSC_S_OFFSET`    | Status |
| DLEN     | 2          | `BSC_DLEN_OFFSET` | Data Length |
| A        | 3          | `BSC_A_OFFSET`    | Slave Address (7-bit) |
| FIFO     | 4          | `BSC_FIFO_OFFSET` | Data FIFO |
| DIV      | 5          | `BSC_DIV_OFFSET`  | Clock Divider |

### 4.2 Control Register (C) Bits

| Bit | Macro       | Description |
|-----|-------------|-------------|
| 0   | BSC_C_READ  | 1 = read transfer; 0 = write transfer |
| 4   | BSC_C_CLEAR | Clear FIFO (bits 4:5) |
| 7   | BSC_C_ST    | Start Transfer |
| 15  | BSC_C_I2CEN | I2C Enable |

### 4.3 Status Register (S) Bits

| Bit | Macro       | Description |
|-----|-------------|-------------|
| 0   | BSC_S_TA    | Transfer Active |
| 1   | BSC_S_DONE  | Transfer done (W1C) |
| 2   | BSC_S_TXW   | TX FIFO needs writing |
| 3   | BSC_S_RXR   | RX FIFO needs reading |
| 4   | BSC_S_TXD   | TX FIFO can accept data |
| 5   | BSC_S_RXD   | RX FIFO has data |
| 6   | BSC_S_TXE   | TX FIFO empty |
| 7   | BSC_S_RXF   | RX FIFO full |
| 8   | BSC_S_ERR   | ACK error from slave |
| 9   | BSC_S_CLKT  | Clock stretch timeout |

### 4.4 Write Transfer Sequence

From RAF_030, canonical I2C write of two bytes (register address + value):
1. Write `DONE | ERR | CLKT` to S to clear sticky flags.
2. Write 7-bit slave address to A.
3. Write byte count to DLEN.
4. Write `I2CEN | CLEAR` to C to enable I2C and flush FIFO.
5. Write register byte then value byte to FIFO.
6. Write `I2CEN | ST` to C to start transfer.
7. Poll S until `DONE = 1`.
8. Write `DONE` to S to clear the flag.

Example clock divider from RAF_030:
```c
bsc[BSC_DIV_OFFSET] = 0x05DCu;  // 0x05DC = 1500; 150 MHz APB / 1500 = 100 kHz
```

## 5. Clock Manager (CM) — PWM Clock (offset from base 0x3F101000)

Source file: RAF_031.

The Clock Manager controls the PWM clock source and divisor. The PWM peripheral
base is 0x3F20C000; the CM base is 0x3F101000. Their separation is:
`0x3F20C000 - 0x3F101000 = 0x10B000` bytes.

In RAF_031, `cm_base` is derived from `pwm_base` using this constant offset.

### 5.1 CM PWM Register Offsets

| Register     | Byte offset from CM base | Word index | Macro |
|--------------|--------------------------|------------|-------|
| CM_PWMCTL    | 0xA0                     | 40         | `CM_PWMCTL_OFFSET` |
| CM_PWMDIV    | 0xA4                     | 41         | `CM_PWMDIV_OFFSET` |

### 5.2 CM Password

Every write to a CM register must have the password OR'd into the high byte:
```c
#define CM_PASSWD  0x5A000000u
```
Writes without this password are ignored by the hardware.

### 5.3 CM_PWMCTL Bits

| Bit | Macro              | Description |
|-----|--------------------|-------------|
| 0-3 | CM_PWMCTL_SRC_*    | Clock source select |
| 4   | CM_PWMCTL_ENAB     | Enable clock |
| 5   | CM_PWMCTL_KILL     | Kill (stop) clock immediately |
| 7   | CM_PWMCTL_BUSY     | Clock running (read-only) |

| Source value | Macro                | Frequency |
|-------------|----------------------|-----------|
| 1           | CM_PWMCTL_SRC_OSC   | 19.2 MHz oscillator |
| 6           | CM_PWMCTL_SRC_PLLD  | 500 MHz PLLD |

### 5.4 CM_PWMDIV Format

`CM_PWMDIV` bits 23:12 hold the integer divisor (DIVI); bits 11:0 hold the
fractional divisor (DIVF). To set DIVI=5 (PWM clock = 500 MHz / 5 = 100 MHz):
```c
cm_base[CM_PWMDIV_OFFSET] = CM_PASSWD | (5u << 12);
```

### 5.5 CM Stop/Start Sequence

The sequence required to safely change the PWM clock (from RAF_031):
1. Stop PWM: write 0 to PWM CTL.
2. Kill CM clock: write `CM_PASSWD | CM_PWMCTL_KILL` to CM_PWMCTL.
3. Wait for `CM_PWMCTL_BUSY` to clear.
4. Set new divisor: write `CM_PASSWD | (DIVI << 12)` to CM_PWMDIV.
5. Enable clock with source: write `CM_PASSWD | CM_PWMCTL_ENAB | SRC` to CM_PWMCTL.
6. Wait for `CM_PWMCTL_BUSY` to set (clock locked).
7. Configure PWM range, duty, and enable PWM channel.

## 6. PWM Peripheral (base 0x3F20C000)

Source files: RAF_031, RAF_034.

### 6.1 Register Map

| Register | Byte offset | Word index | Macro              | Description |
|----------|-------------|------------|--------------------|-------------|
| CTL      | 0x00        | 0          | `PWM_CTL_OFFSET`   | Control |
| STA      | 0x04        | 1          | `PWM_STA_OFFSET`   | Status |
| DMAC     | 0x08        | 2          | `PWM_DMAC_OFFSET`  | DMA Configuration |
| RNG1     | 0x10        | 4          | `PWM_RNG1_OFFSET`  | Channel 1 Range (period) |
| DAT1     | 0x14        | 5          | `PWM_DAT1_OFFSET`  | Channel 1 Data (duty) |
| FIF1     | 0x18        | 6          | `PWM_FIF1_OFFSET`  | FIFO Input |
| RNG2     | 0x20        | 8          | `PWM_RNG2_OFFSET`  | Channel 2 Range |
| DAT2     | 0x24        | 9          | `PWM_DAT2_OFFSET`  | Channel 2 Data |

### 6.2 CTL Register Bits

| Bit | Macro         | Description |
|-----|---------------|-------------|
| 0   | PWM_CTL_PWEN1 | Channel 1 Enable |
| 1   | PWM_CTL_MODE1 | Serialiser mode (1) vs PWM mode (0) |
| 2   | PWM_CTL_RPTL1 | Repeat last data when FIFO empty |
| 3   | PWM_CTL_SBIT1 | Silence bit (output when idle) |
| 4   | PWM_CTL_POLA1 | Polarity invert |
| 5   | PWM_CTL_USEF1 | Use FIFO for Channel 1 |
| 6   | PWM_CTL_CLRF1 | Clear FIFO |
| 7   | PWM_CTL_MSEN1 | M/S Enable (Mark-Space mode) |
| 8   | PWM_CTL_PWEN2 | Channel 2 Enable |
| 15  | PWM_CTL_MSEN2 | Channel 2 M/S Enable |

### 6.3 DMAC Register

| Bit field | Macro                 | Description |
|-----------|-----------------------|-------------|
| [31]      | M034_PWM_DMAC_ENAB    | Enable DMA |
| [15:8]    | M034_PWM_DMAC_PANIC(n) | DMA panic threshold |
| [7:0]     | M034_PWM_DMAC_DREQ(n)  | DMA request threshold |

### 6.4 FIFO Audio Mode

RAF_034 configures PWM for 44100 Hz audio output using serialiser mode with
DMA feeding the FIFO. The configuration sequence:
1. Write `PWM_CTL_CLRF1` to CTL to clear FIFO.
2. Set RNG1 to 32 (one serialiser word = 32 bits per sample).
3. Write DMAC with `ENAB | PANIC(7) | DREQ(3)`.
4. Write `USEF1 | MODE1 | PWEN1` to CTL to enable serialiser+FIFO mode.
5. Prime the FIFO with the first batch of samples (DMA takes over after).

Square wave generator for self-test (440 Hz at 44100 Hz sample rate):
```c
uint32_t period = 44100u / 440u;   // ≈ 100 samples per cycle
// First half of each period: 0xFFFFFFFF (high)
// Second half: 0x00000000 (low)
```

## 7. DMA Engine (base 0x3F007000)

Source files: RAF_032, RAF_033.

### 7.1 Control Block Structure

Each DMA transfer is described by a control block (CB) that must be
256-bit (32-byte) aligned in hardware use. The project struct:

```c
typedef struct {
    uint32_t ti;          // Transfer Information
    uint32_t source_ad;   // Source Bus Address (RUNTIME)
    uint32_t dest_ad;     // Destination Bus Address (RUNTIME)
    uint32_t txfr_len;    // Transfer Length (bytes)
    uint32_t stride;      // 2D Mode Stride
    uint32_t nextconbk;   // Next Control Block physical address (or 0 = end)
    uint32_t _pad[2];     // Reserved, must be 0
} rafaelia_dma_cb_t;
```

Total size: 8 fields x 4 bytes = 32 bytes.

### 7.2 Transfer Information (TI) Bits

| Bit range | Macro                      | Description |
|-----------|----------------------------|-------------|
| 0         | DMA_TI_INTEN               | Interrupt enable on completion |
| 3         | DMA_TI_WAIT_RESP           | Wait for write response before proceeding |
| 4         | DMA_TI_DEST_INC            | Destination address increments |
| 8         | DMA_TI_SRC_INC             | Source address increments |
| 11:8      | DMA_TI_BURST(n)            | Burst transfer length |
| 20:16     | DMA_TI_PERMAP(n)           | Peripheral mapping (DREQ source) |
| 25:21     | DMA_TI_WAITS(n)            | Wait cycles between writes |
| 26        | DMA_TI_NO_WIDE_BURSTS      | Restrict to 128-bit bursts |

### 7.3 Linear Chain (RAF_032)

A two-element chain where CB0 points to CB1, and CB1 has `nextconbk = 0` (stop):
```
CB0 (txfr_len=16, nextconbk=&CB1) -> CB1 (txfr_len=0, nextconbk=0) -> stop
```
CB0 TI flags: `SRC_INC | DEST_INC | WAIT_RESP`.

### 7.4 Circular Ring (RAF_033)

A two-element ring where CB0 points to CB1 and CB1 points back to CB0.
Used for continuous streaming without CPU intervention:
```
CB0 (txfr_len=64, nextconbk=&CB1) -> CB1 (txfr_len=64, nextconbk=&CB0) -> ...
```
The source and destination addresses in both CBs are RUNTIME values (physical
bus addresses, not virtual addresses). The DMA engine uses bus addresses
directly; the `source_ad` and `dest_ad` fields must be populated by the
caller after mapping contiguous physical memory.

## 8. Access Methods

### 8.1 /dev/mem (Full Peripheral Access)

RAF_021 maps the GPIO peripheral via `/dev/mem`:
```c
#define BCM_GPIO_BASE   0x3F200000UL
#define GPIO_BLOCK_SIZE 0x1000

int fd = open("/dev/mem", O_RDWR | O_SYNC);
void *gpio_map = mmap(NULL, GPIO_BLOCK_SIZE,
                      PROT_READ | PROT_WRITE, MAP_SHARED,
                      fd, (off_t)BCM_GPIO_BASE);
```
Requires root or `CAP_SYS_RAWIO`. Returns TOKEN_VAZIO (0) without failing
if `/dev/mem` is not available (non-RPi host).

### 8.2 /dev/gpiomem (GPIO Only, Unprivileged)

RAF_022 uses `/dev/gpiomem`, which is available without root on Raspbian
for the `gpio` group:
```c
int fd = open("/dev/gpiomem", O_RDWR | O_SYNC);
void *gpio_map = mmap(NULL, GPIO_BLOCK_SIZE,
                      PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
```
The offset is 0 because `/dev/gpiomem` is pre-offset to the GPIO base.

### 8.3 /dev/mem with Controlled Range (RAF_023)

RAF_023 demonstrates `mmap` with an explicit offset and a larger block covering
multiple peripherals. Same pattern as RAF_021 but with a configurable
`phys_offset` parameter allowing mapping of any peripheral block.

## 9. Hardware Gating

All peripheral operations in the project are wrapped in:
```c
#if defined(RASPBERRYPI)
    // real hardware path
#else
    return 0;  // TOKEN_VAZIO — hardware not present
#endif
```
Self-tests that do not require actual hardware (DMA CB struct verification,
audio buffer generation) run on any host and validate the data-structure logic.
